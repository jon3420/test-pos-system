## A. Production Modified (1 file)

### `public/js/geo-ga4-h1-panel.js`

- SHA256 (H1.4.2): `3f4c89f17e214ab249c4a83fc24b6edc77ab727b27fd2175693bfd3c378dd12`
- SHA256 (H1.4.3): `44fbb670b204a7e2cbe888b75ee8ed0c0a93c912dfa44907a97ccb5e9b9f1ed`
- Line count: 949 → 1004 (+64 lines added, -9 lines removed/replaced, net +55)

Changes (verified against actual diff, not recalled from memory):

1. **Cross-range stale-cache fallback fix (the real production bug).**
   `geoGa4H1State` gained a `lastGoodRangeKey` field alongside the existing
   `lastGoodPayload`. A new pure helper `_geoGa4H1FetchRangeKey(mode, opts)`
   builds an identity string from the actual transport mode **and** the
   actual `startDate`/`endDate` (not just `mode`, since `90d`/`180d`/
   `this_year`/`last_year`/`single`/`custom` can all transport as
   `apiRange==='custom'`). `geoGa4H1Refresh()` now only reuses
   `lastGoodPayload` as a stale fallback when
   `lastGoodRangeKey === currentRangeKey`; on a genuine failure for a
   *different* range, it renders a clean empty/error state instead of
   silently re-displaying the previous range's rows.
2. **Overseas/Other display disambiguation.** `_geoGa4H1RowLabel()` now
   calls a new pure function `_geoGa4H1RawContextSuffix(r)` that appends the
   row's raw `country_raw`/`region_raw`/`city_raw` to the `Unknown` /
   `Overseas／Other` / `Ambiguous` label when available, so two distinct
   unresolved raw GA4 locations no longer render as two visually identical
   rows. `raw_location_key` itself is untouched — this is presentation-only.
3. **Visible resolved-range label.** `geoGa4H1RenderStatus()` gained an
   optional third parameter (`rangeLabel`); `geoGa4H1Refresh()` now passes
   the resolver's `displayLabel` for historical mode (and explicitly `null`
   for realtime mode), so the actual date window in use is visible next to
   the sync status — mirroring what the Dashboard side already showed.
4. **Export surface additions.** `_geoGa4H1RawContextSuffix` and
   `_geoGa4H1FetchRangeKey` were added to `module.exports` so tests can call
   the real production functions directly instead of re-implementing them.

No other function in this file was touched. No change to fetch URLs, DOM
structure outside the status line, wheel/map lifecycle code, or Manual Sync
logic.
