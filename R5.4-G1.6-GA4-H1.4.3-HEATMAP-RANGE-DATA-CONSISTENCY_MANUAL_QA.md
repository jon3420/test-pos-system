## Range Failure QA (the actual H1.4.3 fix — most important manual check)

**CACHE-01.** Select 近7天 and confirm it loads data. Then select a range
you know has no synced data yet (or, if you can simulate a network
failure — e.g. disconnect briefly during the fetch — do so on a different
range). Confirm the Table/Map/status do **not** continue showing 近7天's
rows. Expected: empty state or error state for the new range, never the
previous range's data.

**CACHE-02.** Select a range that has already loaded successfully once.
Trigger a transient failure on a *repeat* load of that **same** range (if
reproducible — e.g. brief network interruption while re-syncing the same
selection). This is allowed to fall back to the last successful load for
that same range, with a "資料可能過期" / last-successful-cache indicator.
This is the one case where showing old data is correct — confirm the
indicator is present so it's not confused with fresh data.
