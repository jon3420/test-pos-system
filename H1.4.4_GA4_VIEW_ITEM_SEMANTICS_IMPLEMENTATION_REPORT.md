# H1.4.4_GA4_VIEW_ITEM_SEMANTICS_IMPLEMENTATION_REPORT

## 1. Baseline
`fix18-10-hotfix30-B5-R5.4-G1.6-GA4-H1.4.3-GA4-HEATMAP-RANGE-DATA-CONSISTENCY-QA-full.zip`

## 2. Production Manual Symptom
Fresh incognito, new GA4 Property. Realtime showed `activeUsers=1`, `page_view=1`,
`session_start=1`, `first_visit=1`. The tester opened the first product card once.
GA4 Realtime `view_item` count rose to 9.

## 3. Reality Audit
Full call-chain trace (see `H1.4.4_GA4_VIEW_ITEM_DUPLICATE_REALITY_AUDIT.md`):

```
renderMenu() → buildCard(p) ×N → _setupViewProductObserver()
  → IntersectionObserver(threshold:0.5).observe() on every .prod-card
  → any card visible on/after render → _trackEvent('view_product', {product_id})
      → POST /api/analytics/events (internal, unaffected)
      → AnalyticsPlatforms.trackPlatformEvent('view_product', pp)
          → GA4_EVENT_MAP['view_product'] === 'view_item'  ← root cause
          → gtag('event', 'view_item', ...)
```

## 4. Original Tracking Flow
`view_product` was designed (fix18-10-hotfix23-A) as a viewport-impression signal —
fired once per product card as it becomes visible, independent of any click. It runs
on every `renderMenu()` (initial load, category switch, search). On a typical mobile
viewport several cards are visible immediately, so `_setupViewProductObserver()` calling
`observe()` on already-visible elements fires their callback immediately.

## 5. Root Cause
**WRONG EVENT SEMANTICS — impression-to-view_item mapping bug.** `analytics-platforms.js`
mapped the list-impression signal `view_product` directly to GA4's ecommerce event
`view_item`, which per GA4 semantics represents a user viewing a single product's detail.
More precisely: the observed `view_item=9` was caused by product-card impressions
entering the viewport, not by nine duplicate handlers attached to the clicked card.
The timing of the manual test made the count appear associated with the click, but the
two are causally unrelated — impressions fire independently of any click.

## 6. Product View Semantic Finding
Confirmed by reading `buildCard()`/`renderProductGrid()` in both `line-order.html` and
`line-shipping.html`: **no product-detail view interaction currently exists.** No modal,
drawer, detail page, or click reaction of any kind on the product card. The only
`detailSheet`/`fetchAndShowDetail()` in the codebase is for order lookup, unrelated to
products. Therefore no normal production user path can legitimately send GA4 `view_item`
today — this is intentional, not a tracking gap.

## 7. Final Fix
`public/js/analytics-platforms.js` — removed `view_product: 'view_item'` from
`GA4_EVENT_MAP`. `view_product` continues to flow to:
- internal `/api/analytics/events` (unaffected)
- Meta `ViewContent` via `META_EVENT_MAP` (unaffected, unchanged)

It no longer reaches GA4 `view_item`. No `view_item` key exists in `GA4_EVENT_MAP` —
by design, until a legitimate product-detail interaction exists.

## 8. Rejected Invisible-Click Approach
During development, a product-card click → `view_item` hook (`handleProductCardView()` /
`bindProductViewDelegation()`) was prototyped to give `view_item` a data source. Reality
Audit proved product cards have no detail-view interaction, so this tracking-only click
hook — invisible to the user — was rejected and fully reverted before the final gate.
Final production does not invent a product-view interaction. `line-order.html` and
`line-shipping.html` are byte-identical to the H1.4.3 baseline.
