## Test Harness Findings (test-only, not production bugs)

**Finding 1 — JSDOM timer leak.** `public/js/app.js`, when `eval()`'d into a jsdom `window` (as all these runtime suites do), starts a WebSocket-reconnect `setTimeout` chain. Each of the ~30 fresh test environments created per runtime file never closes its `window`, so these chains accumulate and keep the Node event loop alive indefinitely — the process does not exit on its own even after all assertions and the summary have printed. Fix: an explicit `process.exit(process.exitCode)` immediately after `printSummary()` returns, matching the convention already used in `run-g1-6-ga4-h1-4-1-geo-dashboard-cleanup-runtime.js`. This exit only occurs after all async assertions have settled and the summary has been printed — verified by confirming the printed PASS/FAIL/TOTAL numbers are identical whether or not the process happens to be killed by an external timeout.

**Finding 2 — Regression runner partial-fail interim state.** Documented above under Strict Full Regression; not used as final evidence.
