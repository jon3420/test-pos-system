## A. Production Modified (3 files)

### `public/js/geo-intelligence-map.js`
- `geoInitMap()`: newly-created Leaflet map instance now defaults
  `scrollWheelZoom.disable()` immediately after `L.map(container)` (Problem 1
  root cause — Leaflet's own default is `true`, and it was never configured
  anywhere in the codebase before this change).
- `geoRenderMapBlock()`: canvas wrapped in a `position:relative` wrapper div
  with a new sibling `#${containerId}-wheel-hint` badge (hidden by default,
  text driven by `geo-heatmap-ui.js`); canvas itself gained `tabindex="0"`
  for keyboard accessibility.
- No new `L.map()` call, no new tile layer, no second map — same single
  Leaflet instance contract preserved (verified by Target Runtime `D18`/`E86`
  and Static Audit `I4`).

### `public/js/geo-heatmap-ui.js`
- New `dashboardMapInteractionState` (Map UX state, deliberately kept
  separate from `dashboardGa4State`/`geoGa4H1State`) plus
  `geoDashboardMapActivate()` / `geoDashboardMapDeactivateForHeatmap()` /
  `geoDashboardMapEnableWheel()` / `geoDashboardMapDisableWheel()` /
  `geoDashboardMapBindWheelLifecycle()` / `_geoDashboardMapUnbindWheelLifecycle()`
  and the click/keydown/outside-click handlers.
- `geoHeatUiSwitchTab()`: heatmap branch now calls
  `geoDashboardMapDeactivateForHeatmap()` (wheel stays enabled, Dashboard's
  own listeners unbound); dashboard branch now calls
  `geoDashboardMapActivate(mapContainerId)` (always resets to disabled —
  does not remember the prior enabled state).
- `geoHeatUiRenderPanel()`: now renders a `#${containerId}-heat-diagnostics`
  mount that consumes `window.__geoHeatUiDiagnosticsHtml` (see below) — this
  is the new Heatmap-side ownership of the moved diagnostics.
- **Bug fix (real Production DOM bug, not test-only):** the Heatmap Engine's
  own Order/Visitor ranking list already used `${containerId}-ranking`. Once
  the legacy Top-3/ranking table moved into the same Heatmap panel, its
  identical id collided with this pre-existing, unrelated feature. Fixed by
  renaming the legacy table's id to `${containerId}-legacy-ranking` (2 call
  sites: the div itself in `geo-intelligence.js`, and the
  `getElementById(geoLastContainerId + '-ranking')` lookup used by its
  re-render helper). See §H below and the Reality Audit for full details.

### `public/js/geo-intelligence.js`
- `refreshGeoDashboardKpiBlock()`: the Dashboard panel template
  (`#${containerId}-panel-dashboard`) no longer includes
  `kpiCards`/`fulfillmentLine`/`renderGeoQualityBlock(...)`/
  `decisionCenterHtml`/`emptyStateNotice`/`rankingSectionHtml`/
  `sharedMetricBarHtml` — unconditionally, with no fallback branch for when
  `geo-heatmap-ui.js` isn't loaded (a fallback was drafted and explicitly
  rejected per the Final Dashboard Geo DOM Contract; see Reality Audit).
- All of the above are instead concatenated into
  `window.__geoHeatUiDiagnosticsHtml`, assigned *before*
  `geoHeatUiRenderPanel()` is invoked in the same function call (so the
  first render already has the Heatmap panel populated — no second refresh
  needed).
- Legacy ranking table div id renamed `${containerId}-ranking` →
  `${containerId}-legacy-ranking` (see bug fix above); its re-render lookup
  updated to match.
- No function was deleted. `renderGeoQualityBlock()`,
  `geoComputeRecommendedActions()`, `computeGeoTopAreas()`,
  `_renderGeoAreaRankingTable()`, `geoVisitorMetricBarHtml()` (via
  `geo-heatmap-ui.js`/`geo-visitor-layer.js`) are all unchanged and still
  called — only where their output is mounted in the DOM changed.
