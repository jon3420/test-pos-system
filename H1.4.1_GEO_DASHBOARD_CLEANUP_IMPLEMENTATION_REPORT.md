# H1.4.1 — Geo Intelligence Dashboard Cleanup — Implementation Report

## Goal

Cleanup (not rebuild) of three UI problems found after deploying H1.4:

1. Dashboard map's mouse wheel always zoomed the map, hijacking normal page
   scroll.
2. GA4 regional markers (new, real data) and POS Visitor Geo
   diagnostics (Unknown %, Geo Quality) rendered side-by-side on the same
   Dashboard panel, looking contradictory.
3. An old 8-metric selector (visitors/add-to-cart/checkout/orders/revenue/
   conversion/cart-abandon/recommendation-risk) and its "no data" states
   showed on Dashboard even though nothing there could resolve.

## Baseline

`fix18-10-hotfix30-B5-R5.4-G1.6-GA4-H1.4-MAP-STATE-QA-full.zip` (H1.4 final).
The cancelled H1.5 workdir was never referenced or used.

## Reality Audit Findings

See `H1.4.1_GEO_DASHBOARD_CLEANUP_REALITY_AUDIT.md` for the full audit and
Final Findings. Summary: `scrollWheelZoom` was never configured anywhere
(Leaflet default `true` in effect); the 8-metric bar rendered outside both
tab panels (visible on both tabs); POS diagnostics and Recommended
Actions/Top-3/ranking rendered unconditionally on Dashboard regardless of
tab. Top-3/ranking table confirmed by code-dependency inspection to read the
legacy `vm` object (`/funnel`, `/county-summary`, `/alerts`), not GA4
persisted data.

## Production Changes

### Map Wheel UX (`geo-intelligence-map.js` + `geo-heatmap-ui.js`)

- New map instances default `scrollWheelZoom.disable()`.
- Dashboard: click-to-enable (map click → enable; Esc or outside click →
  disable; re-entering Dashboard always resets to disabled, never remembers
  the prior state).
- Heatmap: always enabled, no click gate.
- `+`/`-` zoom control unaffected in all states (separate Leaflet handler).
- Same Leaflet map instance shared by both tabs throughout — no second
  `L.map()` anywhere.
- New interaction state (`dashboardMapInteractionState`) kept deliberately
  separate from `dashboardGa4State`/`geoGa4H1State` (pure map UX, not GA4
  query state).
- Idempotent listener binding — repeated tab switches don't add duplicate
  listeners (verified: a single Esc dispatch after 20 round trips triggers
  exactly one `disable()` call, not 20).

### Dashboard / Heatmap Ownership (`geo-intelligence.js` + `geo-heatmap-ui.js`)

- Dashboard panel keeps only: tab bar, map, GA4 regional-overview label/
  range/disclaimer, and the refresh control. Unconditionally — no fallback
  branch reintroduces diagnostics when `geo-heatmap-ui.js` isn't loaded (a
  draft fallback was built, then explicitly removed once the Contract was
  made unconditional).
- Everything else — the 8-metric selector, POS Geo KPI cards, Geo Quality
  badge, Recommended Actions / Decision Center, empty/all-unknown notices,
  and the legacy Top-3/ranking table — now renders only inside the Heatmap
  panel, via a single hook (`window.__geoHeatUiDiagnosticsHtml`) assigned
  before `geoHeatUiRenderPanel()` consumes it, so the first render already
  has it (no second refresh needed).
- No function, API call, or computation was deleted. Every moved block is
  the exact same render function, just mounted in a different place.

### Duplicate-ID Fix

The Heatmap Engine's own Order/Visitor ranking list and the legacy Top-3
table both used `${containerId}-ranking`. Moving the legacy table into the
Heatmap panel exposed a real collision. Fixed by renaming the legacy id to
`${containerId}-legacy-ranking` (2 call sites). See Production Diff and
Reality Audit Finding 8 — classified as a real Production bug, not test-only.
