## 0. 摘要

本輪只補兩個已重現的前端缺口。

**缺口 A：確認 GET 沒有等待上限**
- 新增獨立的 **10 秒上限**；PATCH 維持 **15 秒**。
- 上限涵蓋請求與回應內容解析，到期一定結束流程，不會只呼叫 abort 卻繼續等待。
- 到期後解除本操作自己的 busy 與 mutation pending。
- 值保持「未知」，不當成未參與；畫面提示「暫時無法確認，將重新更新狀態」，由既有自動更新取回伺服器狀態。

- 讀取失敗同樣依序號判斷，舊的失敗不會把較新的成功資料標成待更新。

### 3.2 修正

`_pdApTimed(run, ms)` 的做法：
- 把整段 `run(signal)`（`apiFetch` 加上 `res.json()`）和計時器一起 `Promise.race`。
- 到期時先 `abort`，再直接 resolve `{timeout:true}`，不等待未結束的 Promise。
- 正常完成或例外都會 resolve，計時器一定在 `finally` 清除。

PATCH（15 秒）與確認 GET（10 秒）都改用它。確認逾時、失敗或回應無法解析時：

| 項目 | 處理 |
|---|---|
| 商品值 | 設為 `'unknown'`：勾選框為不確定狀態且 disabled，不送出任何設定 |
| 提示 | 「暫時無法確認，將重新更新狀態」，持續顯示到取得確定值為止 |
| busy | 只清除自己的：以操作物件比對 `busy[pid] === op`，不會清掉後來另一個操作的忙碌狀態 |
| mutation pending | 由 `_pdMutEnd()` 解除 |
| 後續 | 觸發既有的 `pdAutoRefreshNow('mutation')`。下一次成功讀取（自動或手動）取得確定值後，清除提示並恢復可操作 |
| 晚到回應 | 逾時後才到的確認回應或 PATCH 回應已不被等待，不會寫入任何狀態 |
| 不做的事 | 不重送 PATCH，不另開確認輪詢 |

### 4.2 修正：與既有防護並存

讀取序號：
- `_pdAuto.ap.readSeq` 單調遞增，換店時也不歸零。
- `/snapshot`、`rnAutoLoad()`、確認 GET 都在**發出時**取號，存放在 `ctx.rseq`。

`_pdApApply(auto, err, ctx, rowIds)` 依序判斷：

| 順序 | 檢查 | 不通過時 |
|---|---|---|
| 1 | 身分世代：`ctx.gen` 必須等於目前的 `gen`（換店、換帳號、登出、權限失效時遞增） | 整筆不套用 |
| 2 | 全店欄位（自動開關、總開關、完整度、參與集合）：`rseq` 必須大於 `gseq` | 不套用全店欄位；開關另外仍受既有 `_pdMutBlocks('autocfg')`、`'notify'` 保護 |
| 3 | 各商品：商品在 busy 中，或 `_pdMutBlocks('auto:'+pid)` 為真 | **跳過，也不更新該商品序號** |
| 4 | 各商品：`rseq` 必須大於該商品的 `pseq[pid]` | 不套用該商品 |

第 3 項代表：儲存中被略過的商品，不會被誤認為已經取得較新的確定值，之後的確認 GET 或 snapshot 仍能正確套用，也不會誤解鎖。

儲存成功時，該商品的序號會更新為「回應到達時」新取的號。在 PATCH 送出之前就發出的讀取，即使晚到也不會蓋過儲存結果；這與 `_pdMutBlocks` 的防護互相重疊、互為保險。

讀取失敗：
- 適用於 snapshot 失敗或缺少 `auto`、設定 GET 失敗、確認 GET 失敗或逾時。
- 呼叫 `_pdApReadFail(ctx)`：只有 `rseq` 同時新於最後一次成功與最後一次失敗時，才標成待更新。
- 標成待更新時保留最後成功的勾選與數值，不顯示 0／0，也不取消勾選。
- 摘要的「待更新」改由這個依序判斷的狀態決定，不再直接使用 snapshot 的 `failCount`。
- 列表上方原有的「⚠ 資料可能尚未更新」警示仍由 `failCount` 控制，與原本相同，因為那是總表資料本身是否更新。

只依序號判斷、不依各 API 分別計數：三個來源共用同一組 `gseq`、`pseq`。
