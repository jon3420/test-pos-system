- **目標**：店家在補貨通知商品列表直接勾選「恢復販售通知」，不必逐一開啟「明細 → 查看」；同時清楚區分「收集登記」與「恢復販售自動通知」。

### 3.2 `app.js` 變更

- **列表新欄位**：每列「☐ 參與」，文字標籤可點，鍵盤空白鍵可切換，`aria-describedby` 指向下方簡短狀態。
- **共用狀態** `_pdAuto.ap`：
  - 列表與明細都讀寫同一份資料。
  - 伺服器確認值、儲存中、回饋文字、全店開關、身分世代（`gen`）。
- **儲存** `pdAutoPartToggle()`：
  - 列表與明細（`rnAutoProduct()` 改為呼叫它）共用。
  - 沿用 `PATCH /restock/auto/products/:id`。
- **讀取**：
  - 隨既有 `/snapshot` 自動更新套用（`_pdApApply()`）。
  - `rnAutoLoad()` 也改走同一套用流程。
  - `rnAutoProductState()` 不再發 GET，只依共用狀態重繪。
- **摘要** `#pd-auto-state`：`自動通知：已開啟｜通知發送總開關：已開啟｜已選擇 N／M 項商品`，並說明「已選擇」不代表已符合資格或已發送。
- **商品條件提示**（保留勾選）：
  - 「已選擇，待開啟自動通知」
  - 「已選擇，待開啟通知發送總開關」
  - 「已選擇，必要設定尚未完整」
- **明細勾選**：
  - 開啟明細時立即依共用狀態顯示（未知時為載入中）。
  - 附註「與商品列表『恢復販售通知』欄是同一個設定」。
- **文案**：
  - 明細通知面板：原「修改庫存或商品狀態不會自動發送」改為區分手動（須預覽並確認）與自動（商品已參與且全店自動與總開關開啟時，依自動規則另行發送）。
  - 上方 `#pd-notify-state`：「由店家手動預覽並確認發送」改為同時說明手動與自動條件。
- **其他**：
  - 載入、空清單、錯誤、登入失效列 `colspan` 6→7。
  - 商品列重建時保留 `.pd-auto` 焦點。

## 4. API／snapshot 擴充

- **沒有新增端點**，也沒有新增公開設定端點。
- `GET /api/product-demand-admin/snapshot` 是既有的管理端唯讀整合查詢，本輪最小幅度擴充：

  ```
  auto: { enabled, enabled_at, send_enabled, notify_available, config_complete, missing, participating_product_ids: [..] }
  auto_error: ''   // RA.getConfig 讀取失敗時為 'AUTO_CONFIG_UNAVAILABLE'，auto 為 null；總表其他部分照常回應
  ```

- 資料來源是既有的 `RA.getConfig()`（唯讀），與 `GET /restock/auto` 相同。
- 沿用既有 `requireStaffJwt`＋`line_order` 權限，店別只信任 JWT。原有欄位都不變。
- **刻意不回傳全店 epoch 與商品參與版本**：前端不模擬版本，「相同值重複儲存版本不變」完全由後端既有規則處理（新驗收 B2）。
- 寫入沿用既有 `PATCH /api/product-demand-admin/restock/auto/products/:id`，後端未修改。
