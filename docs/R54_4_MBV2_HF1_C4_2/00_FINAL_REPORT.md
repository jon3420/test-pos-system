## 1. 前台入口延遲：根因與修正

### 1.1 根因（C4.1 實測）

`_initProductDemand()` 雖然開始讀 `/api/product-demand/config`，但流程是：

```
await 會員 Gate（LIFF SDK 載入／初始化／被動辨識） → await config → await 本人登記 → _refreshAllDemandRows()
```

而 `buildCard()` 首次渲染時 `_demandConfig.enabled=false`，入口列是空的（`.demand-row:empty{display:none}`）。因此：

- LIFF 已設定時，**一般入口要等 LIFF SDK 與會員 Gate 完成**才出現；SDK 卡住時永遠不出現（新測試 P1-1 在 C4.1 失敗）。
- 入口出現時商品卡從 221px 長到 247px（+26px，P2-4／P3-4 量到），頁首「我的想買登記」也是本人資料回來後才出現（P3-5）。
- 本人查詢的回應沒有綁定送出時的 session：查詢期間本機 session 換成另一位會員，仍會把上一位的「已登記 2 份」顯示出來（P5）。
- 本人查詢失敗時，頁首清單顯示「目前沒有有效的想買登記」，等同誤稱沒有登記（P4-2）。

## 2. 後台總表與明細不一致：根因與修正

### 2.1 根因（不是統計 API 算錯）

`adminSummary()` 與 `adminDetail()` 使用同一個有效條件（`status='active' AND expires_at > datetime('now')`）。截圖的「總表 1 人 1 份、明細 0 人 0 份＋上一筆已取消 3 份」是**載入時機不同**造成：

- 明細只在按「查看」時讀一次（`openDemandDetail()`），之後不再更新；
- 總表只在進入分頁、儲存設定等時機以 `loadDemandAdminTab()` 重讀，而且每次先把表格清成「載入中…」；
- 兩區從不在同一時點讀取，所以先開明細、之後顧客新增登記、再因儲存設定重讀總表，就會出現截圖的組合。

前端沒有硬改數字；改為同一次讀取、同一輪套用。

### 2.2 唯讀整合 API

`GET /api/product-demand-admin/snapshot[?product_id=]`（沿用 `requireStaffJwt`＋`line_order`，店別只信任 JWT）：在同一個同步區段內呼叫既有 `adminSummary`、`getCapability`，以及（有商品時）`adminDetail`、`listBatches`，因此總表、明細、批次是同一資料時點。只讀取，不寫入。商品不存在時明細回 `detail_error='PRODUCT_NOT_FOUND'`，總表照常回傳。

### 2.3 自動更新（`public/js/app.js`）

| 規則 | 實作 |
|---|---|
| 進入分頁立即讀取 | `lpmRenderActiveTab()` → `loadDemandAdminTab()` → `pdAutoEnter()` |
| 每 10 秒 | 單一 `setTimeout` 鏈；只有在 LINE 商品管理頁、補貨登記分頁、頁面可見時排程。批次「發送中」期間縮短為 2 秒（取代 C4 的獨立 2 秒批次輪詢，避免兩組輪詢）。 |
| 立即更新 | 恢復可見（`visibilitychange`）、視窗取得焦點（1.5 秒內不重複）、重新進入分頁、手動「🔄 重新整理」、店家操作完成後、其他分頁登出／換店（`storage`）。 |
| 停止並使舊回應失效 | 離開分頁（`lpmSwitchTab`）、離開頁面（`showPage`）、頁面隱藏、401／403：`_pdHalt()` 遞增 epoch、清 timer、abort 進行中的請求。登出本來就會重新載入頁面。 |
| 不累積 | 監聽器全頁只註冊一次（`_pdAuto.wired`）；任何時候最多一個 timer。 |

| 舊回應不覆蓋 | 回應套用前比對 epoch、登入身分＋店別（token＋store_id）、展開商品與明細版本；店家操作以序號判斷：讀取送出後有任何收集開關／設定／通知開關／批次操作（進行中或已完成），該欄位不套用本輪回應，等下一輪。 |
| 換店／登出／權限 | 身分改變先清除畫面上的上一個身分資料（表格、明細、通知能力），再讀取新身分；401／403 停止輪詢並顯示「登入已失效或沒有權限」。 |

### 2.4 不打斷操作

- 不再重跑會清空表格的載入：總表依商品列逐格更新數字、狀態與收集勾選（商品增減才重建，並把焦點還給同一列）。
- 未儲存的總開關與有效天數：輸入過就標記 `settingsDirty`，儲存成功前不覆蓋；有焦點的欄位不覆蓋。
- 正在送出的收集／通知開關：送出期間停用該勾選，完成前後的讀取不覆蓋。
- 展開明細：通知面板只在「查看」時建立一次，自動更新只更新標題數字與明細表 `tbody`（內容相同不重畫），日期、取餐方式、預覽內容與批次識別保持（A18）。
- 批次清單：內容相同不動；有變動時保留已展開的批次明細並以唯讀 API 重新讀取該明細；切換商品後的延遲回應不寫入。
- 捲動位置、焦點保持（A18-5 在實際捲動容器上量測）。
- 「最後更新：HH:MM:SS（台北時間）」只在成功套用後更新；失敗時保留原資料，顯示「⚠ 資料可能尚未更新（連線暫時失敗，將自動重試）」，不跳出通知；重試間隔 15→30→60 秒。

自動更新只呼叫 `GET /snapshot`（以及展開中的批次明細 `GET /restock/batches/:uuid`）：不建立預覽、不確認、不續送、不寫入（A8、A18-7、A26）。
