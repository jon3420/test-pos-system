# R54.4／MBV2-HF1-C2：商品詳情數量上限邊界修正報告

> 基準：R54.4／MBV2-HF1-C1
> ZIP：`P3CD_DEPLOY_R54_4_MBV2_HF1_C1_PREORDER_CART_AND_PRODUCT_STATUS_FIX_APP_ROOT.zip`
> SHA-256：`2c9e95b080dacc1c5f4f9387359936586d70edbb8fb22bd5758f78a79205e67d`
> C1 的全部修正（統一加購驗證、送單日期防呆、三分頁販售標示）原樣保留；本輪只改一個函式的一段邏輯，並在 `checkCartIncrement()` 回傳值多加兩個欄位。
> 本輪仍未加入商品需求登記／補貨通知。

## 一、重現與根因

**重現（已在 C1 實際重現）：** 預購剩 20 份，購物車已有同商品 20 份，選了未來日期後開商品詳情。

C1 的實測結果：
```
{"restored":20,"btnDisabled":false,"btnText":"加入購物車","badge":"","incOk":false,"incBucket":"preorder","incLimit":20,"pDate":"2026-11-11","maxQty":1}
```
`checkCartIncrement()` 判定不能再加（`incOk:false`），但詳情的加入按鈕仍可按，上限顯示 1。

**根因：** `openProductDetail()` 用的是 `resolveCartQuantityPolicy()`。這個函式回傳的是總可用額度，不含購物車已有的數量。
詳情再用 `Math.max(1, limit - inCart)` 算上限，剩 0 份時被算成 1 份，而且沒有停用加入按鈕。
同樣的問題也發生在今日額度：今日剩 3 份、購物車已有 3 份或更多時，加入按鈕仍可按。

## 二、修正（`public/line-order.html`）

1. `openProductDetail()` 改為直接呼叫 `checkCartIncrement(id, p, 1)`，跟商品卡＋、購物車＋、`addCart()` 用同一個判斷：
   - **已達或超過上限**：停用加入按鈕，按鈕與標籤顯示「今日額度已達上限」或「預購額度已達上限」。
   - **未達上限**：`maxQty = 額度 − 購物車已有數量`。剩 1 份時上限是 1，可以正常加入 1 份。
   - **額度未設限**：`maxQty = null`，不設上限。
   - 其他無法加入的原因（預購已滿、暫停販售等）沿用 C1 的標示。
2. `checkCartIncrement()` 在數量超出時，回傳值多帶 `limitReached:true` 與 `inCart`，讓詳情能區分「額度用完」和「其他原因」。原有的 `ok`／`message`／`bucket`／`limit` 都不變。
3. 減少和移除不受影響：`chgQty()` 減少數量時本來就不經過這道驗證。

### 1. C2 商品詳情矩陣（真實 server.js＋暫存 SQLite＋真實 Chrome）

| 情境 | 今日額度（每日 3 份） | 預購額度（每日 20 份，已選明天） |
|---|---|---|
| 未達上限 | 購物車 1 → 可加入，上限 2 | 購物車 5 → 可加入，上限 15 |
| 剩 1 份 | 購物車 2 → 上限 1，加入後變 3，再開詳情顯示已達上限 | 購物車 19 → 上限 1，加入後變 20，再開詳情顯示已達上限 |
| 剛好達上限 | 購物車 3 → 停用「今日額度已達上限」 | 購物車 20 → 停用「預購額度已達上限」（**原重現案例**） |
| 超過上限 | 購物車 5 → 停用「今日額度已達上限」 | 購物車 23 → 停用「預購額度已達上限」 |

每個情境都另外確認了以下幾點：
- 詳情能否加入，跟 `checkCartIncrement(id, p, 1).ok` 一致，額度種類（今日或預購）和日期也一致。
- 已達或超過上限時，商品卡「＋」同樣被擋，但可以減少一份。
- 預購 20 份達上限時，減 1 份後再開詳情，會恢復可加入、上限 1；之後可以全部移除，保存的購物車也同步清掉。

## 五、部署後最短驗收

1. 找一個測試商品，把預購份數設為 20。在點餐頁選明天的日期，加到 20 份後開商品詳情：加入按鈕應停用，並顯示「預購額度已達上限」。
2. 在購物車減 1 份，再開詳情：應可加入，數量上限為 1。
3. 今日份數設為 3，購物車加 3 份後開詳情：應顯示「今日額度已達上限」。
4. C1 的驗收步驟（舊購物車轉預購、三分頁暫停標示）照舊執行一次。
