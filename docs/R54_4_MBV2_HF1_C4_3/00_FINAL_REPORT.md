## 1. 三項問題：根因、修正、前後結果

同一支新增測試 `scripts/smoke-r54-4-mbv2-hf1-c4-3-async-consistency.js` 先在未修改的 C4.2 執行，再於 C4.3 執行。重疊的做法：Playwright 先讓請求**送達伺服器並取得回應**（`route.fetch()`，因此回應內容是伺服器當下的舊快照），再扣住回應；期間以正式路由完成新的操作；最後才放行舊回應。不是在請求送達前延遲，也沒有先等待慢查詢完成。

### 1.1 問題一：儲存期間的新輸入被覆蓋（`public/js/app.js`）

**根因**：`saveDemandSettings()` 成功時直接設 `settingsDirty=false`，沒有區分「這次送出的內容」與「送出之後的新編輯」。送出 45 天後使用者改成 60，45 天的成功回應把未儲存狀態清掉，下一輪自動更新（`_pdApplyConfig()`）就以伺服器的 45 天覆蓋畫面上的 60。

**修正**：
- 新增編輯版本 `_pdAuto.settingsRev`：總開關 `change`、有效天數 `input`／`change` 每次編輯都遞增（同時標記未儲存）。
- 儲存時記下送出當下的版本；成功時**只有版本仍相同**才清除未儲存狀態。送出後有新編輯 → 保持未儲存，最新輸入不被儲存結果或自動更新覆蓋，使用者再次儲存才寫入。
- 失敗時不清除；重複儲存時各次各自比對版本，最後一次送出完成且之後沒有編輯才清除。
- 既有保護不變：有焦點的欄位不覆蓋、儲存進行中與完成前發出的讀取不套用（操作序號）。

### 1.2 問題二：通知批次明細被較早的回應倒退（`public/js/app.js`）

**根因**：`restockBatchDetail()` 只檢查商品與明細版本（`openPid`／`detailEpoch`），同一批次多次查詢沒有先後判斷；手動查詢（按「明細」）也不檢查自動更新週期與登入身分。因此「待發送」的舊回應在「LINE 已受理」的新回應之後抵達時，明細被倒退；舊的錯誤回應也會蓋掉新的成功明細；離開分頁、隱藏頁面或換身分後返回的舊回應仍會寫入。

**修正**：
- 每個批次一組序號 `_pdAuto.batchReq[uuid] = { seq, applied }`，手動與背景（自動更新重讀展開中的明細）共用。只有序號大於「已套用」的回應（成功或錯誤）能寫入；較早的回應一律丟棄。
- 回應時另外確認：商品與明細版本相同、自動更新週期（離開分頁／隱藏會失效）相同、登入身分＋店別相同、分頁可見。任一不符 → 不寫入。
- 因生命週期改變而丟棄的查詢標記為待更新；回到分頁後的下一輪自動更新（即使批次清單沒變）會以唯讀 API 重讀該明細。
- 背景查詢失敗保留原內容；手動查詢失敗只有在它是最新一次查詢時才顯示錯誤。
- 發送、防重送、retry key、續送與嘗試上限都沒有改動（B10：模擬 LINE 呼叫 2 次、每位 1 次嘗試）。

### 1.3 問題三：取消成功後，舊本人查詢讓畫面又顯示已登記（`public/line-order.html`）

**根因**：`_loadMyDemands()` 的查詢序號只處理「查詢與查詢」之間的先後。查詢送出後若顧客完成新增、修改、取消或撤回同意，舊查詢晚到時序號仍是最新，就以舊快照覆蓋剛完成的異動。另外，異動回應時若本機 session 已換成另一位會員，舊會員的 401 會把**目前會員**標成登入過期（`_demandAuthExpired` 是全域旗標）。

**修正**：
- 世代 `_pdMineGen`：新增／修改份數（`_submitDemand`）、取消（`_cancelDemand`）、撤回同意（`_revokeDemandConsent`）在**開始與結束**都遞增，並記錄進行中的異動數。
- 本人查詢記下送出時的世代；回應（成功、失敗或 401）時世代已改變或仍有異動進行中 → 丟棄。異動仍在進行 → 標記，異動結束時重新查詢一次；異動已完成 → 立即以目前世代重查一次。
- 同一 session、同一世代、尚未完成的重新查詢共用同一個請求（`_pdReloadMine()`），不重複送出。
- 異動回應時 session 已換人（`_pdMemberChangedSince()`）：舊會員的成功、錯誤或 401 都不寫入；關閉舊表單、以目前會員重新確認。
- 登入過期旗標綁定當時的 session（`_pdAuthExpiredFor`）；session 改變即失效（`_pdSyncAuth()`）。
- 既有規則不變：身分確認前不顯示本人資料、查詢失敗不誤稱沒有登記、登入導回只恢復一次、一般入口提前顯示、不阻塞首屏（C4.2 驗收 80 項與 C3.2 首屏測試照常通過）。
