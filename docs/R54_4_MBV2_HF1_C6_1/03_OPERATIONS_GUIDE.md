# 補貨通知營運操作說明（R54.4／MBV2-HF1-C6.1）

> 適用：店家後台「LINE 商品管理 → 補貨登記」。本版以 C6 說明為基礎，補充 C6.1 的自動通知版本防護與中斷恢復行為（第 C、D 節）。
> 所有發送都經 LINE Messaging API。畫面上的「LINE 已受理」只代表 LINE 已收下請求，**不代表顧客已收到或已讀**。系統不會自動退款，也不保證訊息送達。
> **自動通知交付時預設關閉**，商品預設不參與。升級、重啟、匯入、還原都不會替你打開。

## A. 上線前準備（只需一次）

1. 「系統設定 → LINE」已設定 Channel Access Token 與 LINE 會員 LIFF ID（商品直達連結需要）。
2. 補貨登記分頁：勾選「在 LINE 點餐頁顯示補貨登記入口」、設定登記有效天數、選擇消費者訂閱方式，按「儲存設定」。
3. 勾選「啟用 LINE 補貨通知發送」（總開關）。畫面顯示「目前可用」才代表設定完整。總開關關閉時，手動與自動都不會發送。

## B. 手動發送（原本的方式，維持不變）

1. 點商品的「查看」→ 下方「🔔 補貨通知（店家手動發送）」。
2. 選取餐方式與日期（只能選系統判定可訂購的日期）→「預覽名單」。預覽會列出合格人數與各種排除原因。
3. 確認無誤 →「確認發送」。批次會逐筆送出，畫面自動更新進度。
4. 暫停的批次（例如額度用完、服務重新啟動）：確認原因後按「續送未完成項目」。結果待確認者只會以原 retry key 在 23 小時有效時間內重試，不會換新 key 重送。

## C. 恢復販售自動通知

### 開啟前
- 先用手動方式完成一次真機驗收（第 G 節）。
- 在商品明細勾選「🤖 此商品參與恢復販售自動通知」。預設不參與，只勾需要的商品。

### 開啟
- 勾選「恢復販售時自動發送補貨通知」，確認視窗會列出規則：
  - 只在**店家明確恢復販售**（販售狀態改為可販售、取消今日完售、上架、開啟外帶／外送），或**手動增加可售額度**，使商品由不可訂購變為可訂購時觸發。
  - 供應日期＝各取餐方式的最近可訂購日，由伺服器依台北時間、最後接單時間、行事曆、休息日、預訂範圍與額度計算。未來日期以「已開放預購」通知。
  - 只通知已同意、同意屬於目前登記週期、未撤回、未取消、仍為好友、取餐偏好相符的登記。「都可以」同一週期只通知一次（外帶優先）。
- **開啟只建立新的觀測基線**：目前已可售的商品不會追發，也不會追發關閉期間的恢復販售。
- 不會觸發的情況：改名稱／價格／說明、重複儲存相同狀態、每日排程自動恢復、份數每日重設、訂單取消回補、備份還原、搬家匯入。
- 重複儲存相同的開關或商品參與設定，不會產生任何事件，也不會切換版本。

### 查看結果
- 「自動通知紀錄」：每次觸發的時間、商品、日期與取餐方式、狀態，以及每個方式的排入／排除人數與原因。
- 事件狀態：排隊中／處理中／已建立通知批次／未發送（附原因）／已取消／處理失敗／**待店家確認（未自動發送）**（C6.1 新增，見第 D 節）。
- 通知批次會標示「自動」或「自動（已人工接手）」。成效在「營運分析中心 → 補貨通知成效」，可依手動／自動篩選。

## D. 開關變更、舊批次與重啟後會怎樣（C6.1）

每一筆自動通知真正送出前，系統都會重新核對：
- 批次屬於同店、同一觸發事件、同一商品。
- 總開關與必要設定仍允許發送。
- 全店自動通知仍開啟，且仍是**同一次開啟**（epoch）。
- 商品仍參與，且仍是**同一次加入**（參與版本）。
- 原有的同意、好友、需求週期、防重送、商品可訂購性與供應日期仍合格。

核對不通過時，批次會暫停並記錄原因，未送出的項目不會被送出。

| 情況 | 已交給 LINE 的那一筆 | 尚未送出的項目 | 之後 |
|---|---|---|---|
| 送出途中**關閉**自動通知 | 照實保存結果（已受理就是已受理；回應遺失就是結果待確認） | 不送出；維持「待發送」並記錄原因，釋放本週期名額 | 批次暫停「自動通知已關閉」 |
| 送出途中**關閉再開啟** | 同上 | 不送出（舊批次屬於上一次開啟） | 批次暫停「自動通知曾關閉後重新開啟」；不會自動續送 |
| 送出途中**商品退出**自動通知 | 同上 | 不送出 | 批次暫停「商品已退出自動通知」 |
| 送出途中**商品退出後又加入** | 同上 | 不送出（舊批次屬於上一次加入） | 批次暫停「商品曾退出後重新加入自動通知」；不會自動續送 |
| 送出途中關閉總開關、撤回同意、取消需求、停售 | 同上 | 依既有規則暫停或擋下並記錄原因 | 與 C6 相同 |

- **釋放名額的意思**：這些未送出的登記不算已通知。之後在新基線下真正發生的恢復販售，仍可正常通知他們。已受理的人不會再收到。
- 已交給 LINE 的請求不會被撤回或改寫：已受理照常保存；回應遺失維持「結果待確認」，不會改成「確定未送出」，也不會換新 retry key 重送。

### 人工接手（店家明確續送）
- 只有店家在後台按批次的「續送未完成項目」才算人工接手。批次會標示「自動（已人工接手）」並記錄接手人。
- 接手後沿用原逐筆紀錄、原 retry key、原訊息快照與總嘗試次數。之後不受自動開關與商品參與限制，但**仍受**總開關、同意、好友、取消需求、商品可訂購性等共通條件限制。
- 若同一位顧客在這段期間已由其他批次通知（或其他批次占用本週期名額），接手續送時會擋下並標示原因，不會重複送出。
- 重啟、匯入、自動處理程序都不會自行把批次當成人工接手。

### 不想送了
- 在批次按「取消未送出項目」。從未交給 LINE 的項目會取消並釋放週期名額；曾送出（含結果待確認）者保留紀錄、不會補送。

### 服務重新啟動後
| 重啟前的狀態 | 重啟後 |
|---|---|
| 觸發事件已建立、預覽已保存、尚未確認 | 重新核對開關、epoch、商品參與與版本、總開關、同意與可訂購性。仍有效 → **沿用同一份預覽**確認並送出（不重建、不換日期、不擴大名單）。預覽已逾時（30 分鐘）、連結或店別設定不符、商品不可訂購、版本失效 → 安全停止並記錄原因，**不會悄悄重建新預覽追發**。 |
| 已確認、尚未開始送出，或送到一半 | 版本與資格仍有效 → 只續送「從未交給 LINE」的項目（原 retry key）。送出後中斷、結果不明者維持「結果待確認」，由店家決定是否續送。版本失效 → 暫停，不自動續送。 |
| 因開關變更已暫停的舊批次 | 維持暫停，不會被自動撿回。 |
| 已完成、已取消、已作廢 | 尊重原狀態，不會重新發送。 |
| 沒有合格收件人 | 合法發送 0 則，紀錄寫明原因（例如「確認時已沒有合格登記」），與恢復失敗分開顯示。 |

### 升級前（C6）留下的舊資料
- C6 沒有記錄版本。升級到 C6.1 後，無法證明版本的舊自動批次與舊事件**不會**被自動續送或自動發送：
  - C6 可能留下的「事件已完成、但自動預覽從未確認、沒有任何發送紀錄」：事件改標為「待店家確認」，預覽停止並記錄「升級前資料無法確認版本」。
  - C6 因重啟而暫停的自動批次：維持暫停（「無法確認此自動批次的版本」），未送出項目釋放名額。
- 處理方式：確認仍要通知 → 對該批次按「續送未完成項目」（人工接手），或改用手動預覽發送；不需要 → 按「取消未送出項目」。

## E. 備份、匯入與還原

- 全店自動通知開關、epoch、開啟時間屬於保護設定：不匯出、不覆寫，還原後維持目前設定。
- **商品「參與自動通知」與參與版本由本機維護**：匯入或還原不會覆寫既有商品的設定；匯入的新商品一律不參與（版本從 0 起算）。還原後如需自動通知，請重新勾選參與。
- 匯入的通知批次一律標示「由備份匯入」，版本視為無法確認，不會被自動續送；需要時由店家明確續送。

## F. 回退到 C5.4.2 時

- C5.4.2 沒有自動通知功能：回退期間恢復販售**不會**自動發送，手動預覽與發送照常可用，已受理的人會被排除。
- 回退時正在送出的自動批次：C5.4.2 啟動時會把它暫停（服務重新啟動）、不自動續送；送出後中斷者標為結果待確認。
- 資料庫中 C6.1 新增的欄位與 `restock_auto_events` 表在 C5.4.2 不使用，也不影響其運作。
- 再升級回 C6.1：開關與商品參與設定保留；版本仍有效的暫停批次只續送從未交給 LINE 的項目；過時的舊批次維持暫停。
- 限制：回退期間若店家在 C5.4.2 手動續送已釋放名額的舊自動項目，C5.4.2 不會重新取得週期名額。此時防重只靠「已受理／曾嘗試」證據檢查（仍會排除已通知者）。建議回退期間不要續送自動批次，改用手動預覽。

## G. 需求資料匯出

- 補貨登記分頁「匯出需求資料」：選狀態與登記日期（台北）→「⬇️ 統計 CSV」或「⬇️ 明細 CSV」。
- 檔案為 UTF-8（含 BOM），Excel 可直接開啟中文；會員 LINE 識別已遮罩；不含任何權杖或登入資訊。

## H. 真機驗收（最短步驟；尚未執行。完成前請勿開啟自動通知）

1. 測試帳號加入官方帳號好友 → 在點餐頁對一個暫停販售的測試商品「補貨登記」並同意通知。
2. 手動預覽並確認發送 → 手機收到訊息，點連結能開到該商品；成效頁出現 1 次點擊。
3. 勾選測試商品參與自動通知、開啟全店自動通知（總開關需開啟）→ 用第二個測試帳號登記 → 把商品恢復可販售 → 手機收到訊息；「自動通知紀錄」顯示已建立通知批次。
4. 再按一次「可販售」，或停售後再恢復 → 不會收到第二則（紀錄顯示「本週期已通知」）。
5. **C6.1 防護**：用 3 個以上測試帳號登記同一商品 → 恢復販售後立刻關閉再開啟自動通知 → 確認後續帳號沒有收到，批次顯示「自動通知曾關閉後重新開啟」。再按「續送未完成項目」→ 剩下的帳號各收到 1 則。
   - 收件人太少時第一筆可能已送完，請增加測試帳號或改用商品退出／加入測試。
6. 關閉自動通知，確認之後恢復販售不再發送。
7. 匯出明細 CSV，以 Excel 開啟確認中文與欄位正確。
