# R54.4／MBV2-HF1-C6.2 操作說明：補貨登記數量一鍵加購與訂單連動

> 本輪沒有新增設定開關：升級後即生效。不會發送任何通知，也不會回溯處理升級前的訂單。

## 1. 顧客看到什麼

| 情境 | 畫面 |
|---|---|
| 已登入、有登記，開啟商品（含從補貨通知開啟） | 詳情顯示「你尚有 N 份補貨登記」，數量預選為需要補入的份數，按鈕顯示「加入購物車 N 份」。顧客可調整，按下才加入 |
| 購物車已有部分份數 | 只預選差額（例：登記 5、購物車已有 2 → 預選 3） |
| 購物車已有足夠或更多份數 | 提示「登記份數已在購物車中，不會再自動累加」；不會減少顧客手動加的份數 |
| 今日／預購額度不足 | 提示「目前最多只能再加入 X 份，其餘 Y 份需求會保留」 |
| 有 LINE Pay 待付款訂單 | 提示「其中 R 份訂購中（等待付款），不會重複帶入」 |
| 有其他登記商品 | 詳情下方「我的登記商品，一起加入（N）」；頁首「📋 我的補貨登記」也有入口 |
| 未登入 | 與以前相同（從 1 份開始，一般加購照常） |

### 我的登記商品，一起加入

- 清單列出商品名稱、未完成份數、訂購中／購物車已有份數、本次可加入份數、勾選、無法加入的原因。
- 只合併可用**相同取餐方式與供應日期**（今日／預約下個營業日）的商品：
  - 購物車已有商品 → 依購物車的取餐方式與日期。
  - 購物車是空的、且有多種可能 → 顧客先選組合；系統不代選。只有一種可能時直接使用。
- 停售、缺貨、不支援該取餐方式、日期不同、額度不足的商品不會加入，登記保留。
- 按「將勾選商品加入購物車」後，畫面列出實際加入與未加入的商品及原因。

## 2. 份數怎麼算（會員、後台、CSV 共用）

| 名稱 | 意義 |
|---|---|
| 原登記 | 顧客登記的份數（後台「期望份數」） |
| 已完成 | 有效訂單已成立、已扣減的份數 |
| 訂購中 | LINE Pay 已建立訂單、等待付款的份數 |
| 尚待購買 | 原登記 − 已完成 − 訂購中 |

**什麼時候扣減**

| 情況 | 處理 |
|---|---|
| 開啟通知、預選數量、加入或移除購物車 | 不扣減 |
| 現金（及其他非 LINE Pay）訂單成立 | 立即扣減（不等現金付款狀態） |
| LINE Pay 訂單已建立、等待付款 | 標記訂購中 |
| LINE Pay 確認已付款 | 扣減 |
| LINE Pay 付款失敗，或付款請求 30 分鐘內未完成 | 解除訂購中、保留需求；之後若付款成功仍會扣減一次 |
| 未完成訂單被取消或作廢 | 依原綁定回復 |
| 已完成訂單作廢、已完成後退款 | 不自動回復（後台明細可查到待核對紀錄） |

- 剩餘 0 → 登記標記「已完成」，移出有效需求統計；後台明細與會員「已完成的登記」仍可查詢。
- 已完成後顧客可再登記，會建立新的登記週期；舊訂單之後的取消只影響舊週期。
- 顧客修改已有部分成交的登記時，輸入的是「還想購買份數」（不得少於已購買份數）。

## 3. 後台

- 「LINE 商品管理 → 補貨登記」：期望總份數下方顯示「已完成／訂購中／尚待購買／已完成登記筆數」（只有出現訂單連動時才顯示）；明細的份數欄同樣顯示。
- 查詢單一登記的訂單關聯：`GET /api/product-demand-admin/requests/:登記編號/orders`（訂單 UUID、編號、份數、扣減份數、狀態、訂單與付款狀態）。
- CSV：統計與明細在原欄位之後新增「已完成份數、訂購中份數、尚待購買份數、完成時間／已完成登記筆數」，原欄位順序不變。

### 關聯狀態

| 狀態 | 意義 |
|---|---|
| reserved（訂購中） | LINE Pay 待付款 |
| settled（已扣減） | 已扣減 `applied_qty` 份 |
| released（已解除） | 付款失敗、逾期或待付款時取消；需求保留 |
| reverted（已回復） | 已扣減的訂單在未完成前取消／作廢，已回復 |
| review（待核對） | 已完成訂單作廢、作廢前狀態不明、或匯入時來源仍為訂購中。系統不自動處理 |

## 4. 系統行為

- 份數更新都在後端：訂單建立交易內綁定；LINE Pay 付款完成由付款 outbox（`demand_settle`）處理；取消／作廢後同步。
- 啟動後與每分鐘補齊一次：訂購中逾期、付款結果、遺漏的取消回復。只處理本機資料，不呼叫外部 API、不發送通知。
- 所有更新都以目前狀態為條件，重複 callback、查詢、恢復、重啟只會套用一次。
- 份數連動失敗不影響訂單與付款；綁定失敗時訂單照常成立並補綁一次。

## 5. 備份與搬家（MBV2）

- 「商品想買登記」分類新增「登記與訂單的份數關聯」。
- 匯入的關聯一律標記匯入來源，只作為歷史：本環境不會據此扣減、回復或發送通知；來源仍為「訂購中」者改為待核對。

## 6. 升級與回退

**升級**：直接部署。啟動時自動新增 `product_demand_requests.settled_qty`、`completed_at` 與資料表 `product_demand_order_links`（可重複執行）。升級前的歷史訂單不會被扣減。

**回退到 C6.1**：部署上一版 ZIP 即可，資料庫不需處理（舊版忽略新欄位與新表）。回退期間的限制：

| 回退期間 | 影響 | 再升級後 |
|---|---|---|
| 新訂單 | 不連動（不建立關聯、不扣減） | 仍不連動（不回溯） |
| 已綁定訂單付款成功或被取消 | 份數不更新 | 啟動補齊處理一次 |
| 已完成的登記 | 舊版會員清單不顯示 | 正常顯示於「已完成的登記」 |
| 舊版修改份數 | 舊版不檢查已購買份數 | 若登記份數 ≤ 已購買份數，視為已完成 |
| 舊版後台明細 | 已完成的登記狀態顯示為原始值 `completed` | — |

## 7. 第一版不含

- 宅配（冷藏宅配訂單）與快閃場次訂單不連動。
- 不比對登記的取餐偏好：任何取餐方式的有效訂單都會扣減該商品的登記。
- 已完成後的部分退款不自動回復（系統沒有逐項退款資料）。
- 多商品合併通知（下一輪 C6.3）。
- 真機、正式 LINE 與 LINE Pay 驗收尚未進行。
