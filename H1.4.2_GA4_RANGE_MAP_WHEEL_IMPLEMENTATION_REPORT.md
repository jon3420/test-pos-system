# H1.4.2_GA4_RANGE_MAP_WHEEL_IMPLEMENTATION_REPORT.md

## 1. Baseline
`fix18-10-hotfix30-B5-R5.4-G1.6-GA4-H1.4.1-GEO-DASHBOARD-CLEANUP` (final H1.4.1 zip, extracted read-only as the sole baseline for this round).

## 2. Goals
Two reported deployment issues:
1. Dashboard GA4 Range buttons appear not to update the map.
2. Wheel-zoom UX inconsistent between Dashboard (click-to-activate) and Heatmap (always-on).

## 3. Reality Audit
Full findings in `H1.4.2_GA4_RANGE_MAP_WHEEL_REALITY_AUDIT.md`. Summary: Range wiring and persisted-identity computation were both **verified correct** through direct testing (not assumed); the reported symptom was a genuine but different problem — a UX gap, not a bug in the reported subsystem.

## 4. Issue 1 Root Cause
**Dashboard Persisted Data UX Gap.** Not a range-wiring bug, not an identity mismatch. Evidence:
- Range Control's `onChange` reliably calls `geoDashboardGa4Refresh()`.
- The resolved range identity (`mode`/`apiRange`/`startDate`/`endDate`) is correct for all 10 modes.
- Manual Sync's write identity and Dashboard GET's read identity are provably the same for all 10 modes — proven with a real-service, real-temp-DB round trip (`run-g1-6-ga4-h1-4-2-persisted-identity-runtime.js`, 44/44).
- The actual symptom: the selected date range simply had no persisted GA4 Historical data yet. Dashboard's GET-only contract (unchanged from H1.4) then required the user to go find Heatmap's Manual Sync button — a detour that, from a non-technical viewer's perspective, looks like "I clicked the date and nothing happened."

## 5. Dashboard Sync CTA
When a range has zero persisted rows, Dashboard now clears old markers and renders an inline "立即同步並顯示" button in place of the old plain-text redirect message. Clicking it:
1. Sets a per-identity pending flag and disables the button (`同步中…`).
2. POSTs the existing `/api/analytics/ga4-geo/sync` endpoint (same body shape the H1 Heatmap panel's Manual Sync already used) — no new endpoint.
3. On success, re-runs `geoDashboardGa4Refresh()` (GET) — never renders the POST response directly.
4. On failure, clears the pending flag, re-renders a retryable CTA with an error message; old markers are not restored.
5. If the GET after a successful sync still returns zero rows, shows a distinct "同步完成，但目前仍無此區間的 GA4 區域資料" message rather than silently pretending success means data.

## 6. Persisted Identity Verification
See section 4. All 10 modes (today/yesterday/7d/30d/90d/180d/this_year/last_year/single/custom) proven consistent between write and read identity using the real `services/ga4GeoSyncService.js` against a real temporary SQLite DB — not mocked.

## 7. Sync Concurrency
- **Backend (unchanged, verified by source read):** `routes/ga4-geo.js`'s `_lastManualSync` is a per-store (`req.storeId`), 5-second throttle window — not an identity-scoped mutex, not a strict concurrency primitive.
- **Frontend (new):** UI pending display is identity-keyed (`dashboardGa4State.syncPendingKey`) so an unrelated range's sync-in-progress never falsely shows "同步中…" on the currently selected range. Actual dispatch is single-active-request: a different identity's CTA click while one sync is in flight does not send a second POST; it shows "另一個區間正在同步中，請稍候再試" and becomes available again once the in-flight one settles. Backend `429 rate_limited` (if ever actually hit) maps to the same busy copy, not a generic failure message.

## 8. Race Protection
A completing sync (success or failure) only updates the visible UI if the currently selected range identity still equals the identity that was in flight when the sync started (`_geoDashboardGa4RangesEqual`). If the user has switched ranges, the sync's completion is silently absorbed — it does not snap the title, marker set, or selected range back.

## 9. Issue 2 — Wheel UX
Classified as a **post-deployment UX contract change**, not an H1.4.1 defect. H1.4.1: Dashboard click-to-activate, Heatmap always-on. H1.4.2: both tabs click-to-activate, identical contract — activate locks, map click enables, Esc/outside-click locks, tab switch always relocks the newly-active tab. Leaflet's `+`/`-` zoom control and dragging are unaffected; only `scrollWheelZoom` is governed.

## 10. Production Bug #2 — DOM Element Identity Listener Orphan
Found while migrating the H1.4.1 Target Runtime for the Issue 2 change (not a pre-existing known issue). Full root cause and fix in the Reality Audit. Summary: the wheel-lifecycle bind function was idempotent purely by `mapContainerId` string; `refreshGeoDashboardKpiBlock()`'s full re-render recreates the map container with the same id but a new DOM node, orphaning the old listener. Fixed by tracking the actual bound element (`boundCanvasEl`) and rebinding whenever the live element differs from it.
