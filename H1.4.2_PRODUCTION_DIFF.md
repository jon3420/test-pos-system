**`geo-ga4-dashboard-layer.js`** — Issue 1 fix (Dashboard Persisted Data UX Gap):
- Added Dashboard Sync CTA: `_geoDashboardGa4RenderEmptyCta()`, `_geoDashboardGa4SetSyncButtonBusy()`, `geoDashboardGa4SyncNow()`.
- CTA reuses the existing `POST /api/analytics/ga4-geo/sync` endpoint (same `sync_type: 'range'` body shape as `geo-ga4-h1-panel.js`'s existing Manual Sync) — no new endpoint.
- Sync is command-only: success never renders `result.rows` directly; it always calls `geoDashboardGa4Refresh()` (GET) afterward. Single render source preserved.
- Identity-keyed UI pending (`dashboardGa4State.syncPendingKey`), combined with a single-active-request guard matching the backend's existing per-store throttle window (not a new concurrency model, a frontend accommodation of the existing one).
- Race guard (`_geoDashboardGa4RangesEqual`) ensures a completing sync only updates the UI if the user hasn't since switched to a different range.
- `geoDashboardGa4Refresh()` now returns a descriptor (`{rows}`, `{error}`, or `{superseded:true}`) instead of `undefined`, so the CTA handler can distinguish "synced but still empty" from "synced with data" without a second data source.
- `dashboardGa4State` gained `ids`, `mapInstance`, `syncPendingKey` fields to support the CTA's parameterless `onclick` handler.

**`geo-heatmap-ui.js`** — Issue 2 fix (unified wheel UX) + Production Bug #2 fix:
- `geoHeatUiSwitchTab()`'s `heatmap` branch no longer calls `geoDashboardMapDeactivateForHeatmap()` (which auto-enabled the wheel); it now calls the existing `geoDashboardMapActivate()`, the same click-to-activate lifecycle Dashboard already used. `geoDashboardMapDeactivateForHeatmap()` itself is left in place (unused) rather than deleted, to avoid breaking any external direct import.
- **Production Bug #2 fix**: `dashboardMapInteractionState` gained a `boundCanvasEl` field. `geoDashboardMapBindWheelLifecycle()`'s idempotence check previously compared only the `mapContainerId` string; it now also compares the actual live DOM element (`document.getElementById(mapContainerId)`) against the element it bound to last time, and unbinds+rebinds when they differ. This closes a real bug: `refreshGeoDashboardKpiBlock()` recreates the map container div (same id, new element) on every dashboard refresh, and the old id-only check left the click listener attached to the detached old node.
