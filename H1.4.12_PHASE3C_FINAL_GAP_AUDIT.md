## Major finding: RWD (category H) has no real viewport coverage at all

`scripts/smoke-h1-4-12-popup-admin-ui-browser.js` defines `const VIEWPORTS = [...]` with the six viewports (320×568, 360×800, 390×844, 430×932, 768×1024, 1280×800), but this constant is **never referenced anywhere else in the file** — no loop iterates it, no test indexes into it, and `setViewportSize` is never called. The only viewport-related code in the entire 318-assertion suite is a single context-creation default: `browser.newContext({ viewport: opts.viewport || { width: 1280, height: 900 } })`, and no call site ever passes a different `opts.viewport`. **Every single assertion in this suite runs at the same 1280×900 viewport.** The six-viewport requirement in category H is not partially covered — it has zero real coverage, despite the array's presence potentially giving the impression that it does. This is stated as **MISSING**, not PARTIAL.

## Major finding: no XSS injection testing exists

Searched the entire browser suite for script-injection payloads (`<script>`, `onerror=`, `javascript:` URLs) used as test input: zero matches. The suite does have general-purpose `pageerror` tracking (`page.on('pageerror', ...)`, checked in at least two assertions — BR3 on page entry, BR97 during a modal race) and a check for unexpected external hosts on page load (BR3), but neither of these was ever fed an actual adversarial payload (a name field containing `<script>alert(1)</script>`, for example) to prove the DOM renders it as inert text rather than executing it. Category G is **MISSING**, not VERIFIED — the safety net (pageerror listener) exists, but nothing has been thrown into it.

## Major finding: no external-resource-resilience testing exists

Zero matches for blocking Google Fonts, Leaflet, unpkg, or any CDN host and confirming the page still functions or falls back correctly. Category I is **MISSING**.

## Major finding: QR/Links features exist in production but are untested

`public/js/app.js` contains real QR-code and clipboard-copy logic (15 and 25 matches respectively for QR- and clipboard-related code), so category F's underlying features are real, not vaporware — but the browser suite has zero matches for QR rendering, copy-URL, or public-preview-link assertions. This is a coverage gap on a real feature, distinct from the RWD/XSS/external-resource findings above where even the test scaffolding barely exists. Category F is **MISSING** at the test-evidence level while the feature itself is present in production.
